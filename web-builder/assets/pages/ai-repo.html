Project & skill

AI làm gì với repo này

Những việc thường gặp — dựng UI, giữ cho skill dày lên và không lệch, và chọn đúng mức kiến trúc cho project (thích ứng, không nghi thức).

Build UI web

Ráp màn hình từ wb-* + token, bám thang màu (trắng–đen–xám trước, màu chỉ cho status). Không tự chế style.

Thêm primitive mới

Chạy /wb-change: discover → plan → implement → đồng bộ 6 nơi → verify → rà soát tái dùng → review → commit.

Update component đã có

Cùng workflow; sửa xong phải rà toàn repo tìm chỗ thay được bằng bản mới, hoặc áp biến thể/token vừa thêm.

Sync docs ↔ lib ↔ skill

Giữ components-catalog.md, SKILL.md, CSS và demo khớp nhau — lệch một nơi là skill nói dối AI kế tiếp; core scripts/verify.sh (qua adapter) gác cổng khi commit.

So với lib khác

Đối chiếu phạm vi với Bootstrap (bootstrap-comparison.md) để lộ khoảng trống trong bộ component, quyết định thêm gì tiếp.

Tích hợp vào app thật

Class lo phần nhìn; map sang engine hành vi (Radix, Recharts, dnd-kit) mà vẫn giữ nguyên pixel — xem integration.md.

Chọn kiến trúc project

Chạy complexity gate: web nhỏ → one-file fast path; web lớn/dài hạn → synthesize cây tối thiểu vừa đủ. Không nghi thức thừa — xem Architecture.

Đưa finding về upstream

Bug downstream repro trên skill stock = skill-bug; primitive tái dùng = upstream-candidate → báo cáo, không tự vá. Phân loại: problem-routing.md · /wb-intake.
