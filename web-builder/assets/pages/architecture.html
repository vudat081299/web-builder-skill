Architecture — chọn đúng mức, không nghi thức

Web Builder làm UI đẹp (đó là việc chính, ở mọi trang khác). Đây là việc thứ hai: giúp agent chọn cách tổ chức project để còn bảo trì tiếp được. Là năng lực thích ứng, không bắt buộc — đa số build là nhỏ, nên mặc định một file. Bản AI-facing chi tiết: references/project-architecture.md.

info
Nguyên tắc: kiến trúc bạn không cần là ma sát, không phải "phòng xa". Chạy complexity gate trước; nếu là Level 0 thì dừng — đừng bọc một trang landing 200 dòng trong folder, ADR và handoff nó không bao giờ dùng. Tiêu mức tổ chức như cách design-system tiêu màu: mức thấp nhất đủ việc.

Complexity gate — chạy TRƯỚC khi dựng cấu trúc

Một câu hỏi: project này thực sự cần bao nhiêu tổ chức? Trả lời từ yêu cầu + repo hiện có, trong vài giây, trước khi viết cấu trúc.

Level 0 One-file fast path

Mặc định. Một index.html (markup + một <link> tới web-builder.css + chút JS inline). Không .agent/, không docs kiến trúc, không ADR, không folder "để dành".

Level 1 Compact long-lived

Nhỏ nhưng bảo trì thường xuyên: cây nhỏ theo convention framework + một AGENTS.md ngắn làm bản đồ. Thường chưa cần .agent/ nhiều file.

Level 2 Structured / complex

Nhiều unit đổi độc lập, API/state/persistence thật, hay cần handoff rõ: AGENTS.md + .agent/ + docs/architecture — tạo theo nhu cầu, không theo checklist. Chọn mức nhỏ nhất giải quyết được.

Level 0 — giữ một index.html khi TẤT CẢ đúng

  • Một route/trang.
  • Code viết tay HTML+CSS+JS ≲ 1.000 dòng và ≲ 100 KB.
  • ≤ 3 behaviour nhỏ (menu/theme toggle, tabs đơn giản, validation nhẹ).
  • Không backend / auth / database.
  • Không client router / build / SSR.
  • Không tập nhiều unit (lesson/bài/record) cập nhật độc lập.
  • Không state/persistence phức tạp; không bảo trì feature-by-feature qua nhiều session.

Ngưỡng dòng/KB là heuristic đường-nhanh, không phải luật split: vượt ngưỡng thì đánh giá, không tự động tách — một file cohesive 10.000 dòng vẫn có thể đúng (xem recipes và large-static-sites.md).

Khi nào gọi Web Builder — và khi nào KHÔNG

bolt Gọi Web Builder

  • Bắt đầu website/trang mới.
  • Ráp hoặc thiết kế UI đáng kể.
  • Thiết kế / refactor architecture.
  • Thêm screen flow hay khối tính năng lớn.
  • Thêm UI chưa có sẵn local.
  • Đổi shell / layout / design-system.
  • Refactor monolith / site lớn.
  • Điều tra bug nghi thuộc upstream.
  • Update / đóng gói / release skill.

check_circle Routine — KHÔNG cần

  • Sửa copy / nội dung.
  • Update lesson / data.
  • Fix bug nhỏ local.
  • Tái dùng component local có sẵn.
  • Đổi behaviour trong boundary hiện tại.
  • Thêm test local.
  • Resume từ handoff.
  • Refactor nhỏ không đổi architecture.

Trong project có sẵn: đọc AGENTS.md local trước, reuse giải pháp local, đừng restructure chỉ để giống một profile.

Synthesize từ ràng buộc — không có "cây phổ quát"

Đừng với lấy một layout thư mục thuộc lòng. Kiến trúc được tổng hợp từ các lực trước mặt; thứ được chuẩn hoá là hợp đồng khám phá ngữ nghĩa (cái gì · ở đâu · verify sao — ghi trong AGENTS.md), không phải cây vật lý.

requirements responsibilities units of change source-of-truth framework conventions repo hiện có runtime/deploy discoverability verification = kiến trúc của project này

Profile theo loại site (site-profiles.md; sâu nhất là learning site, learning-sites.md) là điểm khởi đầu, không phải preset — không khớp profile nào thì synthesize cây mới là chuyện bình thường.

File decomposition — kích thước là chẩn đoán, không phải luật

Tách theo responsibility · unit-of-change · lookup locality · testability · hiệu năng tool — không theo số dòng. Một file content cohesive 10.000 dòng có thể chấp nhận được; một file 1.000 dòng trộn layout + content + CSS + state + nhiều behaviour thì không. Monolith cần tách → migrate tăng dần (baseline → tách content → styling → behaviour → routes cuối), verify parity từng bước, không big-bang.

Hai vòng đời: upstream ⇄ downstream

Upstream — repo này

Nguồn sự thật cho skill, design-system, architecture knowledge, protocol, và tooling đóng gói/release.

Downstream — site skill dựng ra

Tự chọn Level của nó, giữ AGENTS.md riêng, để agent routine làm tiếp không cần nạp Web Builder.

Vòng lặp khép: một finding downstream được phân loại (problem-routing.md) local hay upstream; nếu thật sự upstream thì báo cáo (khối WEB-BUILDER UPSTREAM REQUIRED) → intake → đổi skill → verify → package → cài lại. Không bao giờ tự vá repo khác từ session downstream. Đó là cách skill dồn chất lượng.
